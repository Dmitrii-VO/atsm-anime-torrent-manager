# astar.bz — устройство источника

Как есть на 2026-08-04. Добыто разведкой живой страницы, см. записи в [[ЖУРНАЛ]] за 03:40 и 11:05.

## Разметка

Список раздач — в статическом HTML, JavaScript не нужен.

```
div.torrent#torrent_<id>_info
└── div.title > a[href="/engine/gettorrent.php?id=<id>"]   → «Серия 235 (844.05 Mb)»
└── div.cont
    ├── div.li_distribute   → Раздают
    ├── div.li_swing        → Качают
    ├── div.li_download     → Скачали
    ├── Размер: 844.05 Mb
    └── Дата: 03-08-2026     (DD-MM-YYYY)
```

Пагинации нет: все серии отдаются одной страницей (в примере 235 штук). Признак смены вёрстки — HTTP 200 без единого `div.torrent`.

## Три вещи, на которых легко обжечься

**Кодировка windows-1251, но в `<head>` лежит ложный `charset=utf-8`.** Поэтому в BeautifulSoup передаётся уже декодированная строка, а не байты — иначе разбор пойдёт по ложному объявлению.

**Без браузерных заголовков — HTTP 403.** Нужны `User-Agent`, `Accept-Language`. Проверено: тот же запрос без них не проходит, с ними отдаёт 200.

**Домен ротируется** (v19 → v30 → …), постоянен только суффикс `astar.bz`. Поэтому в БД хранится `slug` страницы, а хост подставляется и перебирается по списку зеркал; найденное рабочее запоминается в настройках. Без этого подписки протухли бы при следующем переезде.

## Чего на сайте нет

- **magnet-ссылок** — только `.torrent` через `/engine/gettorrent.php?id=<id>`, отдаётся без авторизации, `application/x-bittorrent`;
- **качества релиза** — в разметке поля нет. В имени файла внутри торрента `1080p` встречается, но это ненадёжно и всё равно не нужно: одной серии соответствует ровно одна раздача, выбирать не из чего. Подробнее — запись журнала за 13:30.

## Нестандартные заголовки раздач

Кроме `Серия N` встречаются сборники: `Серии 27-28`, `Фильмы 1-4`. Отсюда поля `episode` + `episode_end` и правило: у сборника номером считается начало диапазона, у «Фильмов» номера нет вовсе. Раздачи без номера сортируются в конец, чтобы не всплывать над свежими сериями.

Именно поэтому дедупликация идёт по `external_id`, а не по номеру серии — см. [[Архитектура и ключевые решения]].

## Как проверить, что источник жив

```bash
python -m pytest -m network
```

Три канарейки: страница парсится, зеркало резолвится, `.torrent` качается без авторизации. Падение этих тестов при зелёных офлайновых означает, что изменился сайт, а не код.

## Заглушка «Проверка безопасности»

С 07.09.2026 сайт умеет отдавать вместо страницы заглушку: HTTP 200, ~3.3 КБ,
UTF-8 (боевые страницы — windows-1251), текст «Проверка безопасности · Проверяем
ваш браузер · Для продолжения включите JavaScript». Отдаётся на **все** адреса,
включая корень, то есть это состояние сайта, а не проблема конкретной подписки.

Кук и `<meta refresh>` в ней нет — проверка целиком на JavaScript, `requests` её
не проходит и проходить не должен: обход защиты от ботов в проект не закладывается.

Парсер опознаёт заглушку по маркерам и сообщает «astar включил проверку браузера»
с состоянием `unreachable`. Важно именно это состояние: до исправления пустая
страница попадала в общий разбор и давала `layout_changed` — «изменена структура
сайта», из-за чего чинить шли парсер, а не ждать.
