# anilibria.top — устройство источника

Второй источник раздач. В отличие от [[astar.bz — устройство источника|astar]] работает через JSON API, а не по разметке — переверстка сайта ему не страшна.

## Адреса

| Назначение | Адрес |
|---|---|
| Релиз целиком | `GET /api/v1/anime/releases/<alias>` |
| Каталог | `GET /api/v1/anime/catalog/releases?limit=N` |
| Поиск по названию | `GET /api/v1/app/search/releases?query=<текст>` |
| Файл раздачи | `GET /api/v1/anime/torrents/<id>/file` → `application/x-bittorrent` |
| Страница для пользователя | `https://anilibria.top/anime/releases/release/<alias>/` |

Старое API `api.anilibria.tv/v3` **снято**, отвечает 410 Gone с указанием на замену. На это стоит живая канарейка: если ответ изменится, значит сервис снова переехал.

Заголовков об ограничении частоты сервис не отдаёт — держим паузу 1 с на всякий случай.

## Модель раздач принципиально иная

Это главное, что нужно помнить.

| | astar | AniLibria |
|---|---|---|
| Раздач на тайтл | сотни, по одной на серию | две-три на весь релиз |
| Что внутри | одна серия | **все вышедшие серии** («1-5») |
| Когда выходит серия | появляется новый торрент | **существующий обновляется на месте** |
| Качество | не публикуется | 1080p + кодек (AVC/HEVC) + тип (WEBRip/BDRip) |
| magnet | нет | есть |

Обновление на месте проверено: у торрента `id` остаётся прежним, а `hash`, `description` и `updated_at` меняются («1-4» → «1-5»).

## Отсюда — ключ дедупликации

`external_id = "<id торрента>:<hash>"`.

Если бы ключом был только `id`, рост пачки не был бы замечен: запись с таким идентификатором уже есть, и новые серии никогда не попали бы в ленту. С hash каждая новая версия пачки — новая запись, а прежняя остаётся в истории.

Побочный эффект: в таблице раздач накапливаются версии одной и той же пачки. Это осознанно — так видно историю выхода.

## Разбор полей

- Номера серий — из `description` вида `1-5` → `episode` и `episode_end`. Отсюда же требование к отображению: «Серии 1-5», а не «Серия 1».
- Поля-справочники (`quality`, `codec`, `type`) приходят объектом `{value, description}` — брать `description`.
- Название — `name.main` (русское), годится для сопоставления со [[Справочники — Shikimori и AniList|справочниками]].
- Постер — `poster.src`, путь без домена.
- Пустой список `torrents` — не поломка разбора: релиз может быть анонсом или заблокирован правообладателем (`is_blocked_by_copyrights`). Сообщаем об этом явно.

## Что это дало приложению

- Впервые заполняется поле `quality` — появляется смысл у правил выбора релиза (ТЗ §9), потому что на одну серию приходится две раздачи с разным кодеком.
- Впервые появляется `magnet` — оживают пункты меню и путь отправки через magnet.
- Показ «до N серии» пришлось починить: он брал `MAX(episode)`, и для пачек «1-5» выводил «до 1 серии». Теперь `MAX(COALESCE(episode_end, episode))`.

## Проверка живости

```bash
python -m pytest -m network
```

Канарейки: свежий релиз из каталога разбирается, у раздачи есть magnet и качество, файл `.torrent` скачивается, старое API по-прежнему отдаёт 410.
