# Справочники — Shikimori и AniList

Обогащение карточки аниме: названия, постер, тип, статус, оценка, жанры, время выхода следующей серии. Это **не источник раздач** — провайдеры ничего не знают про торренты и не участвуют в проверке подписок.

## Разделение ролей

**Shikimori — основной.** Единственный из проверенных, кто **ищет по русскому названию**. Это решающее свойство: подписки заводятся с astar, где заголовок русский, и другого ключа для сопоставления нет.

**AniList — дополняющий.** Нужен ради точного времени выхода серии: Shikimori даёт дату, AniList — минуту и номер эпизода. Ищет по латинице, поэтому вызывается вторым, по romaji из Shikimori. Его отказ не критичен — данные Shikimori сохраняются в любом случае.

## Ограничения и подводные камни

| Что | Значение |
|---|---|
| Лимит AniList | **30 запросов в минуту** (`X-RateLimit-Limit`), отсюда пауза 2 с |
| Лимит Shikimori | явных заголовков нет, просят представляться — шлём `User-Agent: ATSM`, пауза 0.7 с |
| Оценка AniList | в процентах (74), приводится к десятибалльной (7.4) |
| Оценка Shikimori | `0.0` означает «нет оценки», а не ноль |
| Японское название Shikimori | приходит **списком**, а не строкой — на этом уже падала запись в БД |

## Нумерация серий не совпадает с трекером

Самое важное. У «Пожирателя звёзд» на astar **235 раздач**, а Shikimori и AniList показывают **26 эпизодов**.

Ошибки нет ни у кого: китайские дунхуа справочники разбивают по сезонам, а astar нумерует сквозняком. Поэтому `episodes_total` и `episodes_aired` **нельзя использовать как прогресс подписки** — только показывать с явной подписью «по справочнику». В интерфейсе так и сделано, в схеме БД оставлен комментарий, а в живых тестах стоит канарейка, которая напоминает об этом расхождении.

## Сопоставление тайтла

Поиск по «Пожиратель звёзд» возвращает пять вариантов: сам тайтл, второй и третий сезоны и две полнометражки. Брать первый результат вслепую нельзя.

Правило: точное совпадение нормализованного названия (регистр, ё/е, пунктуация не важны) важнее порядка выдачи; если точного нет — берётся первый. Ошибку авто-подбора пользователь исправляет кнопкой «Выбрать тайтл…».

Найденный `shikimori_id` сохраняется, повторное обновление идёт сразу по нему, без поиска.

## Когда запускается

Автоматически при добавлении подписки — карточка не должна приезжать пустой.
Обогащение идёт мимо состояния «занято»: интерфейс не блокируется, а отказ справочника
не выглядит как проблема с только что добавленной подпиской. Отключается настройкой
«Загружать справочные данные при добавлении подписки».

Вручную — кнопкой «Обновить справку». Существующие подписки автоматически не
догружаются: обогащение цепляется к добавлению, а не к проверке.

## Хранение

Отдельная таблица `anime_metadata` (миграция схемы 3), а не колонки в `anime`: данные внешние, обновляются независимо и могут отсутствовать. Удаляются каскадом вместе с подпиской.

## Проверка живости

```bash
python -m pytest -m network
```

Канарейки проверяют, что Shikimori находит по русскому названию, что поля карточки на месте и что AniList отдаёт время выхода для онгоинга.
