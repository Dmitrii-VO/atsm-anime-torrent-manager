# qBittorrent — интеграция

Web API v2. Проверено на qBittorrent 5.2.3.

## Вход: успех — это не строка «Ok.»

Главная засада, стоившая пользователю ложного «неверный пароль» (см. [[ЖУРНАЛ]] за 12:51).

`POST /api/v2/auth/login` отвечает:

| Ситуация | Ответ |
|---|---|
| обычный вход | 200, тело `Ok.` |
| **обход авторизации для localhost** (`WebUI\LocalHostAuth=false`) | **204, пустое тело** |
| неверные данные | 200, тело `Fails.` |
| блокировка после неудачных попыток | 403 |

Поэтому успехом считается любой 2xx, кроме явного `Fails.`. Привязка к строке `Ok.` ломается на распространённой конфигурации.

При включённом обходе авторизации API вообще доступен без логина: `GET /app/version` отдаёт версию сразу.

## Сессия протухает

Клиент может перезапуститься в любой момент — тогда cookie `SID` перестаёт действовать и запросы начинают возвращать 403. Обрабатывается одним автоматическим повторным входом.

## Передача раздачи

Так как astar не отдаёт magnet, основной путь — `POST /torrents/add` с файлом в multipart. Файл скачивается той же HTTP-сессией, что и страница, с теми же заголовками.

Параметры из настроек: `category`, `savepath`, `paused`. Проверено, что категория реально применяется.

Ответ `Ok.` приходит даже на уже существующую раздачу — отличить повторное добавление по ответу нельзя. Отказ — `Fails.`.

## info_hash и статус «скачана»

Хеш считается локально: SHA1 от **исходного среза байтов** словаря `info` в `.torrent`. Пересобирать словарь нельзя — порядок ключей должен остаться нетронутым, иначе хеш не совпадёт.

По хешу `GET /torrents/info?hashes=…` возвращает состояние. Признаком завершённости считаются `uploading`, `stalledUP`, `pausedUP`, `queuedUP`, `forcedUP`.

## Что лежит в самом .torrent

```
announce, announce-list, created by, creation date
info: name, length, piece length, pieces
```

Поля разрешения или кодека **в формате нет**. Единственный намёк на качество — подстрока в `name`, и она ненадёжна.

## Настройка на стороне клиента

Инструменты → Настройки → Веб-интерфейс: включить, задать логин и пароль. Порт по умолчанию 8080. Пароль ATSM хранит в `settings.json` открытым текстом — перенос в Windows Credential Manager остаётся невыполненным.

## Осторожно при сквозных проверках

Реальная отправка ставит серию на закачку по-настоящему. Для проверок использовать `add_paused=true`, иначе клиент начнёт качать сотни мегабайт.

## Последовательное скачивание (потоковый просмотр / стриминг)

qBittorrent поддерживает стриминг за счёт скачивания частей по порядку и заголовков контейнеров в первую очередь:
- При добавлении (`POST /torrents/add`):
  - `sequentialDownload=true` — порядок от начала файла к концу;
  - `firstLastPiecePrio=true` — приоритет первой и последней частей (заголовки moov/EBML).
- Для уже запущенных раздач:
  - `POST /torrents/toggleSequentialDownload` с `hashes=...`
  - `POST /torrents/toggleFirstLastPiecePrio` с `hashes=...`
- Плееры VLC и mpv умеют играть незавершённые файлы (`.part` или целевой путь) напрямую, если скачаны первые 1–2% и файл растёт последовательно.

## Удаление / ротация раздач при обновлении пачки

- `POST /torrents/delete` принимает `hashes=hash1|hash2` и `deleteFiles=true|false`.
- При ротации пачек AniLiberty (`1-4` → `1-5`) старый хеш удаляется с `deleteFiles=false`, чтобы не удалить уже скачанное видео, если папки совпадают.

Реализовано в `TorrentService._drop_replaced()`. Замена опознаётся по диапазону серий:
старая раздача целиком внутри новой **и** диапазоны не равны. Равные диапазоны —
это перезалив той же серии, его не трогаем. У удалённой раздачи обнуляется
`info_hash`, иначе опрос состояний будет спрашивать клиента о несуществующем.
Настройка — «Удалять из клиента пачки, заменённые новыми» (по умолчанию включена).
