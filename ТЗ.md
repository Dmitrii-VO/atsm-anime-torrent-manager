**Версия ТЗ:** 3.1
**Дата:** 04.08.2026
**Изменения относительно v3.0:** объединено с `Доп.txt` (единая лента новых серий, §5); уточнения по результатам технической разведки источника `astar.bz` вынесены в §26 и отражены по тексту пометкой ⚠.

# 1. Цель проекта

Разработать десктопное приложение для Windows, предназначенное для автоматического отслеживания новых торрент-раздач аниме.

После добавления подписки приложение самостоятельно:

- проверяет сайты;
- находит новые серии;
- уведомляет пользователя;
- автоматически отправляет новые раздачи в торрент-клиент (при необходимости).

Главная цель — полностью исключить необходимость вручную открывать сайты для проверки выхода новых серий.

# 3. Способы добавления аниме

## Способ 1 (MVP)

Добавление по ссылке.

Например:

```
https://v19.astar.bz/7788-pozhiratel-zvezd-swallowed-star.html
```

⚠ Домен источника ротируется (v19 → v30 → …). Приложение сохраняет не только полный URL, но и постоянный идентификатор страницы (`slug`), а хост подставляет из настроек с автоматическим перебором зеркал. Ссылка, добавленная сегодня, обязана продолжать работать после смены домена.

## Способ 2 (будущая версия)

Добавление по названию.

Пользователь вводит:

```
Пожиратель звёзд
```

Приложение самостоятельно выполняет поиск по всем поддерживаемым источникам и предлагает выбрать нужное аниме.

# 5. Лента новых серий (стартовый экран)

Вместо того чтобы открывать каждое аниме отдельно, пользователь первым делом видит экран со всеми новинками по всем подпискам сразу.

```
🔥 Новые серии                              [ Скачать всё ]
────────────────────────────────────────────────────────────
Пожиратель звёзд
Серия 235 · 844 Mb · 03.08.2026 · сиды 210
[ Скачать ]  [ В qBittorrent ]  ⋮
────────────────────────────────────────────────────────────
One Piece
Серия 1140
[ Скачать ]  [ В qBittorrent ]  ⋮
────────────────────────────────────────────────────────────
Solo Leveling
Серия 28
[ Скачать ]  [ В qBittorrent ]  ⋮
────────────────────────────────────────────────────────────
```

Требования:

- в ленту попадают только раздачи со статусом «новая» и непросмотренные;
- одна кнопка «Скачать всё» обрабатывает всю ленту с индикацией прогресса;
- после обработки раздача уходит из ленты (помечается просмотренной);
- ⚠ при первом добавлении подписки весь существующий архив серий помечается просмотренным — иначе лента и уведомления захлебнутся сотнями записей. Новинками считается только то, что появилось при последующих проверках.

# 7. Работа с торрентами

Для каждой раздачи отображаются:

- номер серии;
- название;
- размер;
- качество ⚠;
- дата публикации;
- количество раздающих и качающих ⚠;
- тип ссылки (torrent/magnet).

⚠ Уточнения по источнику `astar.bz`:
- поле **качества на странице отсутствует** — колонка остаётся в модели данных и интерфейсе, но заполняется только теми источниками, которые его публикуют;
- **magnet-ссылок нет**, доступны только `.torrent`-файлы. Действия «Открыть magnet» и «Копировать magnet» неактивны для раздач без magnet;
- дополнительно доступны сиды/личи/число скачиваний — их следует показывать, это помогает выбрать раздачу.

Доступные действия:

- Скачать torrent
- Открыть magnet (если доступен)
- Отправить в торрент-клиент
- Копировать magnet (если доступен)
- Копировать ссылку
- Пометить обработанной / вернуть в новые

# 8. Автоматическая отправка

Для каждой подписки можно включить:

☑ Автоматически скачивать новые серии

При обнаружении новой серии приложение самостоятельно:

- получает torrent или magnet;
- отправляет раздачу в торрент-клиент;
- отмечает её как обработанную.

---

# 9. Правила выбора релизов

Пользователь задаёт собственные правила.

Например.

Предпочитать:

- 1080p
- HEVC

Если отсутствует:

- брать 720p

Не скачивать:

- дубликаты;
- уже обработанные релизы.

⚠ Статус в MVP: на `astar.bz` одной серии соответствует ровно одна раздача, качество не публикуется — выбирать не из чего. В MVP реализуется только защита от дубликатов и повторной обработки (по устойчивому идентификатору раздачи). Приоритеты по качеству и фильтры по ключевым словам — версия 2, когда появятся источники с несколькими релизами на серию.

---

# 10. Интеграция с торрент-клиентами

Приоритетная поддержка:

- qBittorrent (Web API) — **основной путь MVP**;
- торрент-клиент Windows по умолчанию (открытие `.torrent` через ассоциацию файлов);
- Transmission (v2);
- Deluge (v2).

⚠ Поскольку источник отдаёт только `.torrent`-файлы, основной сценарий передачи — загрузка файла приложением и отправка его в клиент как вложения (multipart), а не передача magnet-ссылки. Файл скачивается той же HTTP-сессией, что и страница (с теми же заголовками), и кэшируется локально.

Настраиваются:

- адрес, порт, логин и пароль qBittorrent;
- категория;
- папка загрузки;
- приоритет;
- добавлять на паузе или сразу запускать.

# 11. Мониторинг

Приложение работает в фоне.

Проверка выполняется:

- вручную;
- по расписанию;
- при запуске приложения.

Интервал проверки задаётся пользователем.

⚠ Требования к сетевому слою:
- все запросы идут через общую HTTP-сессию с реалистичными заголовками (`User-Agent`, `Accept-Language`, `Referer`) — без них источник отвечает **HTTP 403**;
- таймауты и повторы с нарастающей задержкой;
- пауза между запросами к одному источнику, чтобы не создавать нагрузку;
- вся сетевая работа выполняется в фоновых потоках, интерфейс не блокируется.

# 13. История

Для каждой серии хранится статус:

- найдена;
- отправлена в торрент-клиент;
- скачана (если возможно определить через API клиента);
- ошибка обработки.

⚠ Определение статуса «скачана» требует сопоставления раздачи с задачей в клиенте по хешу торрента. Хеш вычисляется из загруженного `.torrent`-файла. Функция необязательна для MVP.

# 18. Хранилище данных

Используется SQLite.

Основные сущности:

| Сущность | Назначение |
|---|---|
| **Anime** | подписка: название, источник, URL, `slug`, статус, автозагрузка, избранное, результат последней проверки |
| **Release** | раздача: внешний идентификатор, номер серии, размер, сиды/личи, дата, ссылка на torrent/magnet, статус, признак просмотра |
| **History** | журнал действий по раздачам |
| **Sources** | состояние источников (диагностика) |
| **Rules** | правила выбора релизов (задел под v2) |
| **Settings** | настройки приложения |

⚠ **Ключ дедупликации раздач** — пара «аниме + внешний идентификатор раздачи с сайта» (для `astar.bz` это числовой `id` торрента). Он стабилен, не зависит от текста заголовка и переживает смену домена. Номер серии используется только для отображения и сортировки и может отсутствовать, если не распознан.

# 26. Технические характеристики источника astar.bz

Раздел добавлен в версии 3.1 по результатам разведки. Служит спецификацией для парсера.

| Параметр | Значение |
|---|---|
| Отрисовка списка раздач | статический HTML, без JavaScript |
| Контейнер раздачи | `div.torrent` с атрибутом `id="torrent_<id>_info"` |
| Ссылка на файл | `div.title > a[href="/engine/gettorrent.php?id=<id>"]` |
| Текст раздачи | `Серия 235 (844.05 Mb)` |
| Дополнительные поля | `Раздают:`, `Качают:`, `Скачали:`, `Размер:`, `Дата:` |
| Формат даты | `DD-MM-YYYY` |
| Пагинация | отсутствует, все серии одной страницей (в примере — 235) |
| Magnet | отсутствует |
| Качество релиза | не публикуется |
| Авторизация для скачивания `.torrent` | не требуется, отдаётся `application/x-bittorrent` |
| Запрос без заголовков браузера | HTTP 403 |
| Домены | ротируются (`v19`, `v30`, …), суффикс `astar.bz` постоянен |

Признак «изменена структура сайта»: ответ HTTP 200, но ни одного элемента `div.torrent` не найдено.

# 29. Принятые решения по открытым вопросам

1. **Постеры** — загружаются при добавлении подписки, кэшируются в `%APPDATA%\ATSM\posters`
   и показываются в карточке аниме. Ошибка загрузки не мешает добавить подписку.
2. **Пароль qBittorrent** — пока хранится в `settings.json` открытым текстом.
   Перенос в Windows Credential Manager остаётся открытым.
3. **Архив серий** — виден целиком в таблице раздач библиотеки, со статусом «В архиве»,
   чтобы не путать его с новинками.
