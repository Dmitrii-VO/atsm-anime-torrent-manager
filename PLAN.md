## 0. Разведка источника (уже выполнена)

Страница `https://v19.astar.bz/7788-pozhiratel-zvezd-swallowed-star.html` изучена. Факты, определяющие архитектуру MVP:

| Факт | Следствие для реализации |
|---|---|
| Список раздач присутствует в **статическом HTML**, без JS | Хватит `requests` + `BeautifulSoup`/`lxml`. Playwright/Selenium **не нужны**. |
| Каждая раздача: `div.torrent#torrent_<id>_info` | Стабильный селектор + готовый уникальный `id` раздачи. |
| Внутри: `div.title > a[href="/engine/gettorrent.php?id=<id>"]` | Прямая ссылка на `.torrent`. |
| Текст ссылки: `Серия 235 (844.05 Mb)` | Номер серии парсится регуляркой. |
| Блок `div.cont`: `Раздают: 210`, `Качают: 12`, `Скачали: 1869`, `Размер: 844.05 Mb`, `Дата: 03-08-2026` | Есть сиды/личи/дата в формате `DD-MM-YYYY`. |
| На странице 235 раздач одной страницей, пагинации нет | Один GET = полный список серий. |
| **Magnet-ссылок нет**, только `.torrent`-файлы | qBittorrent кормим файлом (`torrents/add` → multipart), не magnet. Пункты ТЗ «Открыть magnet» / «Копировать magnet» в MVP неактивны. |
| `gettorrent.php` отдаёт `application/x-bittorrent` **без авторизации** | Логин/куки в MVP не нужны. |
| **Нет поля качества** (1080p/HEVC) в разметке | Правила выбора релиза (§7 ТЗ) в MVP вырождаются в «одна серия = одна раздача». Модель данных поле `quality` держит, логика правил — версия 2. |
| Прямой запрос `requests` без заголовков → **HTTP 403** | Обязательны реалистичные `User-Agent`, `Accept-Language`, `Referer`. Вынести в конфиг парсера. |
| Сайт сообщает «Актуальный адрес: **V30**.ASTAR.BZ» (ссылка из ТЗ — v19) | Домен ротируется. Нужен **резолвер зеркал**: хранить `slug` страницы, а хост подставлять из настроек + фоллбэк по списку зеркал. Критично для долгой жизни подписок. |

## 1. Границы MVP

**Входит:** подписка по ссылке, библиотека в SQLite, парсинг списка раздач, определение новых серий, лента новинок, ручное скачивание `.torrent`, отправка в qBittorrent, автопроверка по расписанию, Windows-уведомления, системный трей, логи.

**Не входит (v2+):** поиск по названию, парсеры Nyaa/AniLibria/RuTracker, правила выбора релиза, Telegram/Discord, импорт/экспорт, Transmission/Deluge, темы оформления кроме тёмной.

## 2. Технологический стек

```
Python 3.12   PySide6   SQLite (sqlite3 + свой слой репозиториев)
requests   beautifulsoup4   lxml   loguru   APScheduler   pydantic (конфиг/DTO)
pytest + pytest-qt + responses (тесты)   PyInstaller (сборка .exe)
```

ORM не берём: сущностей мало, схема простая, «сырой» SQL с репозиториями быстрее и прозрачнее.

## 4. Схема БД

```sql
PRAGMA journal_mode=WAL;

CREATE TABLE anime (
    id            INTEGER PRIMARY KEY,
    title         TEXT NOT NULL,
    source        TEXT NOT NULL,          -- 'astar'
    url           TEXT NOT NULL UNIQUE,   -- канонический URL страницы
    slug          TEXT NOT NULL,          -- '7788-pozhiratel-zvezd-…' — переживает смену домена
    poster_path   TEXT,
    status        TEXT DEFAULT 'ongoing', -- ongoing | completed | paused
    auto_download INTEGER DEFAULT 0,
    is_favorite   INTEGER DEFAULT 0,
    last_check_at TEXT,
    last_check_ok INTEGER,
    last_error    TEXT,
    created_at    TEXT NOT NULL
);

CREATE TABLE release (
    id            INTEGER PRIMARY KEY,
    anime_id      INTEGER NOT NULL REFERENCES anime(id) ON DELETE CASCADE,
    external_id   TEXT NOT NULL,          -- id из gettorrent.php?id=…  → ключ дедупликации
    episode       INTEGER,                -- NULL, если не распознан
    episode_raw   TEXT NOT NULL,          -- 'Серия 235 (844.05 Mb)'
    title         TEXT,
    quality       TEXT,                   -- зарезервировано под v2
    size_bytes    INTEGER,
    seeders       INTEGER,
    leechers      INTEGER,
    published_at  TEXT,
    torrent_url   TEXT,
    magnet        TEXT,                   -- NULL для astar
    state         TEXT NOT NULL DEFAULT 'new',  -- new|sent|downloaded|error|ignored
    is_seen       INTEGER DEFAULT 0,
    first_seen_at TEXT NOT NULL,
    UNIQUE(anime_id, external_id)
);
CREATE INDEX idx_release_state ON release(state, is_seen);

CREATE TABLE history (
    id         INTEGER PRIMARY KEY,
    release_id INTEGER REFERENCES release(id) ON DELETE CASCADE,
    anime_id   INTEGER REFERENCES anime(id) ON DELETE CASCADE,
    action     TEXT NOT NULL,   -- found|sent|download_error|parse_error
    message    TEXT,
    created_at TEXT NOT NULL
);

CREATE TABLE source_status (
    source       TEXT PRIMARY KEY,
    state        TEXT,          -- ok|unreachable|parse_error|layout_changed
    message      TEXT,
    checked_at   TEXT
);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT);
CREATE TABLE schema_version (version INTEGER NOT NULL);
```

**Ключевое решение:** дедупликация по `(anime_id, external_id)`, где `external_id` — числовой id торрента с сайта. Он стабилен, не зависит от текста заголовка и переживает смену домена. Номер серии — только для отображения и сортировки.

## 5. Контракт парсера (Plugin Manager)

```python
class BaseParser(ABC):
    name: str          # 'astar'
    display_name: str  # 'AniStar'
    domains: list[str] # ['astar.bz']  → сопоставление по суффиксу хоста, любой vNN

    @abstractmethod
    def match(self, url: str) -> bool: ...

    @abstractmethod
    def fetch(self, url: str) -> AnimeInfo:
        """Один GET → метаданные аниме + полный список раздач."""
```

`AnimeInfo(title, url, slug, poster_url, status, releases: list[ReleaseInfo])`
`ReleaseInfo(external_id, episode, episode_raw, size_bytes, seeders, leechers, published_at, torrent_url, magnet)`

Регистрация плагина — сканирование пакета `atsm.parsers` и сбор подклассов `BaseParser`. Добавление источника = один новый файл, ядро не трогается (§18 ТЗ).

Ошибки типизированы: `SourceUnreachable`, `ParseError`, `LayoutChanged` (список раздач пуст, хотя HTTP 200) — ровно под §19 «Диагностика».

### Парсер astar (спецификация)

1. Нормализовать URL: вырезать `slug`, хост подставить из `settings.astar_host` (по умолчанию — хост исходной ссылки).
2. GET с `User-Agent` десктопного Chrome, `Accept-Language: ru-RU`, таймаут 15 с, 3 ретрая с backoff.
3. При редиректе/ошибке — перебрать зеркала `v19…v40.astar.bz`, найденный рабочий хост сохранить в настройки.
4. Заголовок — из `<h1>` (обрезать по `/` до первого варианта названия).
5. Раздачи: `soup.select('div.torrent[id^=torrent_]')`, из каждого:
   - `external_id` — из `id="torrent_46219_info"`;
   - `episode` — `re.search(r'Серия\s+(\d+)', text)`;
   - `size_bytes` — из `Размер: 844.05 Mb`;
   - `seeders`/`leechers` — `div.li_distribute` / `div.li_swing`;
   - `published_at` — `Дата: 03-08-2026` → `%d-%m-%Y`;
   - `torrent_url` — `urljoin(base, a['href'])`.
6. Пустой список при HTTP 200 → `LayoutChanged`.

## 6. Update Service (ядро)

```
for anime in подписки:
    info = parser.fetch(anime.url)
    known = {r.external_id for r in repo.releases(anime.id)}
    new   = [r for r in info.releases if r.external_id not in known]
    repo.insert_releases(new, state='new')
    history.log('found', …)
    if anime.auto_download and new:
        for r in отфильтровать(new):     # MVP: без правил, всё новое
            torrent_service.send(r)      # → state='sent' | 'error'
    repo.update_check_status(anime, ok/err)
    events.emit(...)
```

**Важно:** при **первом** добавлении подписки все найденные раздачи пишутся с `state='new'`, но `is_seen=1` — иначе 235 серий сразу засыпят ленту и уведомления. Новинками считается только то, что появилось при последующих проверках. Пользователь может «показать все серии» в карточке аниме.

Проверки выполняются в `QThreadPool` (или отдельном worker-потоке), GUI не блокируется. Между запросами к одному источнику — пауза 1–2 с, чтобы не долбить сайт.

## 7. Torrent Service — qBittorrent

Web API v2:
- `POST /api/v2/auth/login` (`username`, `password`) → cookie `SID`, кэшируем; при `403` — релогин и один повтор.
- `POST /api/v2/torrents/add` — multipart: файл `.torrent` (скачиваем сами через ту же сессию с UA), плюс `category`, `savepath`, `paused`.
- Проверка соединения в настройках: `GET /api/v2/app/version` → показать версию или ошибку.
- Опционально: `GET /api/v2/torrents/info?hashes=…` для статуса `downloaded` (§11 ТЗ) — берём, если хеш удалось вычислить из `.torrent` (bencode → SHA1 от `info`). Небольшая ручная реализация bencode, без внешних зависимостей.

Фоллбэк на «торрент-клиент Windows по умолчанию» — `os.startfile(путь_к_torrent)`.

Абстракция `BaseTorrentClient.add(torrent_bytes|magnet, category, savepath) -> Result` заранее заготовлена под Transmission/Deluge в v2.

## 8. GUI

Стартовый экран — **лента новых серий** (из `Доп.txt`), это главный сценарий:

```
┌───────────────────────────────────────────────┐
│  ATSM        [Новые 3]  Лента │ Библиотека │ ⚙ │
├───────────────────────────────────────────────┤
│ 🔥 Новые серии                  [Скачать всё] │

│ │ [постер] Пожиратель звёзд                 │ │
│ │          Серия 235 · 844 Mb · 03.08.2026  │ │

```

Экран «Библиотека» — двухпанельный вид из §4 ТЗ: слева список подписок (значок избранного, счётчик новых, дата проверки, индикатор состояния источника), справа детали + таблица раздач с контекстным меню (Скачать `.torrent` / Отправить в qBittorrent / Копировать ссылку / Пометить прочитанным).

Реализация списков — `QListView`/`QTableView` + собственные модели (`QAbstractListModel`) и делегат для карточки. Не `QListWidget`: при сотнях раздач важна виртуализация.

Тёмная тема — единый `theme.qss`, DPI-масштабирование через `Qt::AA_EnableHighDpiScaling` + относительные размеры.

Трей: `QSystemTrayIcon`, меню «Проверить обновления / Скачать всё новое / Открыть / Выход», закрытие окна → сворачивание (с однократной подсказкой). Уведомления — `tray.showMessage()` (нативные тосты Windows), клик по тосту открывает ленту.

## 9. Этапы работ

| # | Этап | Результат / критерий готовности |
|---|---|---|
| 1 | Каркас: структура пакетов, конфиг, логирование, БД + миграции | `python -m atsm` создаёт `%APPDATA%\ATSM\atsm.db` со всеми таблицами; лог пишется |
| 2 | Парсер astar + registry | На сохранённом фикстуре `astar_7788.html` тест извлекает 235 раздач, серия 235 = 844.05 Mb, дата 03-08-2026; живой запрос отрабатывает без 403 |

| 4 | Update Service + диффинг | Подмена фикстура с +1 серией даёт ровно одну запись `state='new', is_seen=0` и запись в `history` |

| 6 | GUI: оболочка, тёмная тема, диалог добавления, библиотека | Подписка добавляется из UI, список раздач виден, кнопки скачивания работают |
| 7 | GUI: лента новинок + «Скачать всё» | Экран ленты собирается из `state='new'`, массовая отправка с прогрессом |
| 8 | Планировщик + фон + трей + уведомления | Приложение сворачивается в трей, проверка по интервалу и при старте, тост при новой серии |
| 9 | Настройки, экран логов, диагностика источников, автозапуск | Все пункты §21 ТЗ применяются без перезапуска; в UI виден статус источника |
| 10 | Полировка + сборка | PyInstaller `--onedir --noconsole`, иконка, запуск на чистой машине |

Этапы 1–5 — «мозг» без UI, каждый покрыт тестами. Этапы 6–8 — то, что пользователь увидит. Оценка при полной занятости: 1–5 ≈ 3–4 дня, 6–8 ≈ 4–5 дней, 9–10 ≈ 2 дня.

## 10. Тестирование

- **Парсер** — на сохранённом HTML-фикстуре (без сети); отдельный тест-«канарейка» с живым запросом, помечен `@pytest.mark.network`, ловит смену вёрстки.
- **Диффинг** — фикстур «до/после», проверка отсутствия дублей при повторной проверке.
- **qBittorrent** — `responses`/мок HTTP, проверка релогина по 403.
- **GUI** — `pytest-qt`, дымовые тесты моделей и открытия окон.

## 11. Риски и как их держим

| Риск | Митигация |
|---|---|
| Смена домена зеркала (v19 → v30 уже произошла) | Хранить `slug`; авто-перебор зеркал; настраиваемый базовый хост |
| Смена вёрстки сайта | Типизированная `LayoutChanged`, статус источника в UI, тест-канарейка |
| 403 / антибот | Общая `requests.Session` с реалистичными заголовками, ретраи с backoff, лимит частоты |
| Нет magnet и качества | Фичи «magnet» и «правила релизов» помечены как v2, модель данных уже готова |
| Много раздач в первой синхронизации | `is_seen=1` при первичном импорте |
| Блокировка UI при проверке | Вся сеть в worker-потоках, связь с GUI только через сигналы |

## Приоритет 1 — второй источник: AniLibria — ГОТОВО

Сделано: парсер `atsm/parsers/anilibria.py`, подписки, magnet, качество и кодек
в карточке. По дороге выяснилось лишнее против плана: проект переехал на
`aniliberty.top`, а раздача обновляется на месте, из-за чего ключ дедупликации
пришлось строить не на `id`. Подробности — в заметке источника и в журнале.


Старое API снято: `api.anilibria.tv/v3` отвечает **410 Gone** с указанием на замену.
Живое API — `https://anilibria.top/api/v1`, отдаёт JSON.

Проверенные эндпоинты:

| Назначение | Адрес |
|---|---|
| каталог релизов | `/api/v1/anime/catalog/releases?limit=N` |
| релиз целиком | `/api/v1/anime/releases/<alias>` |
| поиск по названию | `/api/v1/app/search/releases?query=<текст>` (HTTP 200) |

В карточке релиза у торрента есть поля, которых нет у astar:

```
качество: 1080p | тип: BDRip | серии: 1-11 | magnet: есть
```

Почему это первым:

- архитектура готова — нужен один файл в `atsm/parsers/`, ядро не меняется;
- это API, а не HTML: отпадает целый класс отказов от переверстки сайта;
- появляется **несколько раздач на серию с разным качеством** — только после этого
  осмысленны правила выбора релиза (ТЗ §9), сейчас выбирать не из чего;
- появляется **magnet** — оживают неактивные пункты меню (ТЗ §7);
- есть поиск по названию — закрывает способ 2 добавления подписки (ТЗ §3).

Один источник закрывает четыре пункта плана развития.

## Приоритет 2 — правила выбора релизов (ТЗ §9) — НЕ НАЧАТО

Таблица `rules` в схеме есть с самого начала и **ни разу не используется кодом** —

кто-то читает.

Делать сразу после AniLibria и на её данных (у AniLibria уже есть AVC, HEVC, 1080p, 720p).

Что включает:
- Профиль качества в настройках (глобально и с переопределением на подписку):
  - Разрешение: `1080p > 720p > любое`;
  - Кодек: `HEVC > AVC` (или `AVC > HEVC` для совместимости со слабыми устройствами / старыми ТВ).
- Логика автозагрузки:
  - Сравнение вариантов одной и той же вышедшей серии/пачки по весам предпочтений;
  - Защита от преждевременного скачивания (grace period / задержка), если предпочитаемый релиз обычно выходит на пару часов позже базового.

## Приоритет 3 — замена устаревших пачек раздач в qBittorrent — ГОТОВО

Сделано в `TorrentService._drop_replaced()`: после успешной отправки старые пачки,
целиком перекрытые новой, удаляются из клиента с `deleteFiles=false`. Настройка
«Удалять из клиента пачки, заменённые новыми» включена по умолчанию.

Отклонения от плана ниже:
- связь с предыдущей версией в `release` не заводилась — замена опознаётся по
  диапазону серий (`models.supersedes()`), лишнего поля не потребовалось;
- сравниваются ещё источник и качество, иначе пачка HEVC «съедала» пачку AVC;
- к тому же правилу привязан показ: перекрытые пачки не выводятся в карточке —
  жалоба пользователя была именно про список, а не про клиент.

Проблема обнаружена при интеграции с AniLiberty: раздачи обновляются «на месте» (`1-4` → `1-5`), меняется `info_hash`. Автозагрузка добавляет новый торрент, а старый остаётся в клиенте, дублируя скачанные гигабайты серий.

План реализации:
- Хранить в `release` связь с предыдущей версией раздачи или отслеживать замену по связке `(anime_id, external_id_prefix)`.
- При успешной отправке обновлённой пачки отправлять в qBittorrent команду удаления старой раздачи:
  `POST /api/v2/torrents/delete` с `hashes=old_hash` и параметром `deleteFiles=false` (чтобы сохранить уже скачанные файлы) либо опционально `deleteFiles=true`, если новая пачка полностью перекачивает файлы в ту же папку.
- Настройка в интерфейсе: «Удалять предыдущие версии раздач из qBittorrent при обновлении пачки».

## Приоритет 4 — потоковый просмотр («Смотреть онлайн / стриминг») — ГОТОВО

Сделано: флаги `sequentialDownload` и `firstLastPiecePrio` при добавлении (настройка
«Качать по порядку»), пункт меню «▶ Смотреть потоком» в карточке аниме и
`TorrentService.stream()` — отправляет раздачу, если её нет в клиенте, включает
последовательный режим у уже добавленной, снимает с паузы, ждёт данных и открывает
файл системным плеером.

Отклонения от плана ниже:
- ждём не «1–2 % торрента», а 2 % **конкретного видеофайла**: у пачки «1-21» два
  процента раздачи — это ещё не начало первой серии;
- открывается самый готовый видеофайл раздачи, а не первый по порядку: у пачки это
  ровно та серия, которую клиент уже качает;
- у добавленной раздачи флаги ставятся через `toggle…`, но только после чтения
  текущего состояния — слепой вызов выключил бы уже включённый режим;
- добавлено снятие с паузы: при настройке «добавлять на паузе» смотреть было бы нечего.

Просмотр серии сразу, не дожидаясь полного скачивания файла на диск.

Техническая реализация через qBittorrent:
- qBittorrent Web API нативно поддерживает флаги при добавлении торрента (`POST /api/v2/torrents/add`):
  - `sequentialDownload=true` — загрузка фрагментов строго по порядку (от начала к концу файла);
  - `firstLastPiecePrio=true` — приоритетная загрузка первого и последнего кусков файла (в них лежат метаданные контейнеров MP4/MKV — moov atom, заголовок EBML, индекс дорожек).
  - Для уже добавленных раздач есть переключатели: `POST /api/v2/torrents/toggleSequentialDownload`, `POST /api/v2/torrents/toggleFirstLastPiecePrio`.
- Сценарий просмотра:
  1. Пользователь нажимает «▶ Смотреть потоком» в ленте или карточке раздачи.
  2. Раздача отправляется в qBittorrent с флагами последовательной загрузки.
  3. Как только клиент скачивает индекс и первые ~1–2% видео (контролируется через `torrents/files` или процент прогресса), ATSM запускает видеоплеер (mpv, VLC, MPC-HC) и передаёт путь к растущему файлу (`os.startfile` или прямой вызов плеера). Плееры вроде mpv и VLC нативно умеют воспроизводить растущие файлы без остановки.

## Приоритет 6 — RuTracker: поиск, скачивание, потоковый просмотр — СПЛАНИРОВАН

План переписан 07.09.2026 после разведки на живом сайте и уточнения задачи.
Устройство сайта — в заметке [[RuTracker — устройство источника]].

**Подписок на RuTracker не будет.** Исходный план описывал подписку на тему и
слежение за перезаливами; пользователю оттуда нужно другое: найти фильм по
названию, скачать и посмотреть потоком. Лента новинок и автопроверка не нужны.

### Что выяснилось и меняет план

1. **Сайт закрыт Cloudflare.** `requests` получает 403 «Just a moment… Enable
   JavaScript». Проверку решает браузерный JavaScript; обход в проект не
   закладывается. Единственный путь — ходить сессией, которую пользователь
   открыл сам, то есть его куками.
2. **Куки из Chrome автоматически не достать.** `browser_cookie3` падает на
   App-Bound Encryption (Chrome 152). Значит копирование руками из DevTools.
3. **`bb_session` и `cf_clearance` — HttpOnly**, из `document.cookie` не видны.
   Удобный способ отдать их приложению — «Copy as cURL» из вкладки Network:
   одной вставкой приходят и куки, и User-Agent.
4. **UA обязан совпадать** с браузерным: `cf_clearance` привязан к IP и UA.
5. **Поиск есть готовый**: `GET tracker.php?nm=<запрос>`, до 500 результатов,
   с размером, сидами и датой добавления. Отдельного API не нужно.
6. **RSS нет** (`rss.php` → 404).

### Этап 0 — спайк, до всякого кода

Вставить куки и UA из браузера в скрипт на `requests` и убедиться, что
`tracker.php?nm=…` отдаёт 200 и таблицу, а `dl.php?t=…` — `application/x-bittorrent`.

Это проверка гипотезы, а не формальность: если Cloudflare не пропустит и с
куками, вся затея не работает и остаётся только «папка с torrent-файлами».
Заодно измерить, сколько живёт `cf_clearance` — от этого зависит, насколько
часто пользователю придётся обновлять куки.

### Этап 1 — настройки и хранение доступа

- `RuTrackerSettings` в `atsm/config.py`: `cookies`, `user_agent`, `proxy`,
  `host` (`rutracker.org`, запасной `rutracker.net`).
- Куки дают доступ к аккаунту, поэтому хранить их там же, где пароль
  qBittorrent, — в Credential Manager через уже написанные
  `read_password()` / `write_password()` (обобщить на произвольный ключ).
- В настройках — вкладка источника с полем «Вставьте cURL из DevTools» и
  разбором вставленного: из строки берутся `-H 'cookie: …'` и `-H 'user-agent: …'`.

### Этап 2 — источник

`atsm/parsers/rutracker.py`. Контракт `BaseParser` рассчитан на подписки
(`fetch(url) → AnimeInfo`), а тут нужен поиск, поэтому:

- `fetch()` и `download_torrent()` реализуются честно (тема → одна раздача) —
  это даёт добавление по ссылке `viewtopic.php?t=<id>` даром;
- поиск добавляется **необязательным** методом `search(query, forums=None)`,
  а реестр отвечает на вопрос «кто умеет искать» через `hasattr`. Так же уже
  сделано с `torrent_states` у торрент-клиента: контракт не раздувается ради
  одного источника.

Разбор — `tr.tCenter.hl-tr` из `tracker.php`: `data-topic_id`, раздел, тема,
размер, сиды, личи, дата (`26-Июл-26`, месяцы русские, `strptime` не годится).
Качество и год вынимаются из заголовка темы регуляркой, отдельных полей нет.

Диагностика отдельными состояниями, как у astar с «Проверкой безопасности»:
- Cloudflare (403 + «Just a moment») → «обновите куки», состояние `unreachable`;
- страница входа вместо результатов → «сессия RuTracker истекла».

### Этап 3 — экран поиска

Диалог «Поиск на RuTracker»: строка запроса, таблица (тема, раздел, размер,
сиды, дата), кнопки **«Скачать»** и **«▶ Смотреть потоком»**.

Чтобы переиспользовать `send()` и `stream()`, найденная раздача сохраняется в
базу как обычная: запись `anime` с `source=rutracker` и `auto_check=0` и одна
`release`. Тогда работают и библиотека, и статусы, и удаление, и весь
потоковый просмотр — без единой правки в ядре.

### Чего в этой работе нет

Ленты новинок раздела, автопроверки, правил качества, входа по логину и паролю
(вход делает браузер). Всё это можно добавить позже поверх того же парсера.
