# AGENTS.md

## Перед работой

- Общение, интерфейсные тексты, комментарии, документация и коммиты — на русском.
- Сначала прочитать `vault/Заметки/Грабли.md` и тематическую заметку из
  `vault/Заметки/`. Требования находятся в `ТЗ.md`, текущий план — в `PLAN.md`.
- После значимой работы дописать снизу `vault/ЖУРНАЛ.md`; старые записи не
  исправлять. Фиксировать неверные гипотезы и тупики, а не пересказ дифа.

## Команды

- Установка: `pip install -r requirements.txt` (Python 3.12+).
- Безопасная проверка запуска:
  `python -m atsm --data-dir D:\atsm-test-data --no-gui`. Без `--data-dir`
  приложение использует реальный профиль `%APPDATA%\ATSM`.
- Все офлайновые тесты в PowerShell:
  `$env:QT_QPA_PLATFORM='offscreen'; python -m pytest`.
- Файл или один тест:
  `python -m pytest tests/test_update_service.py` или
  `python -m pytest tests/test_update_service.py::test_single_new_episode_detected`.
- Живые сетевые канарейки запускаются отдельно: `python -m pytest -m network`.
  По умолчанию `pytest.ini` исключает их; они обращаются к внешним сервисам.
- Отдельных lint, format и typecheck-команд в репозитории нет.
- Не собирать `.exe` без явной просьбы. Запущенный `ATSM.exe` надо закрыть:
  сборка успевает повредить `dist/` перед `PermissionError`. Команда сборки:
  `python tools/make_icon.py && pyinstaller atsm.spec --noconfirm`.

## Устройство

- `atsm/__main__.py` — CLI; `atsm/app.py:bootstrap()` создаёт пути, настройки,
  логирование, мигрированную БД и `AppContext`; `atsm/gui/application.py` запускает
  Qt. `run_atsm.py` существует только как совместимая точка входа PyInstaller.
- `atsm/core` содержит сценарии, `atsm/db` — SQLite и репозитории,
  `atsm/parsers` — плагины источников, `atsm/metadata` — Shikimori/AniList,
  `atsm/torrent` — qBittorrent, `atsm/gui` — Qt UI.
- Новый парсер должен находиться в `atsm.parsers`: реестр импортирует модули и
  принимает только подклассы `BaseParser` из этого пакета. Одновременно добавить
  модуль в `hiddenimports` файла `atsm.spec`, иначе плагин пропадёт из `.exe`.
- Начальная схема лежит в `atsm/db/schema.sql`. Изменение существующей БД — новая
  запись в `MIGRATIONS` и увеличение `SCHEMA_VERSION`; старые миграции не менять.
- БД использует одно соединение между GUI и воркерами, защищённое внутренним
  замком. Не обходить `Database.transaction/query` прямым параллельным доступом.

## Критичные инварианты

- Фоновую Qt-задачу запускать через `WorkerRunner`: он удерживает `Worker` до
  доставки сигнала. Голый `QThreadPool.start(worker)` случайно теряет результаты.
- Для делегатов недостаточно создать виджет: GUI-тест должен вызвать `paint` в
  pixmap. Произвольный длинный текст обязан быть обрезан и не расширять окно.
- Цвета UI брать только из `atsm/gui/palette.py`; QSS строится из
  `theme.qss.tmpl` через `string.Template`, не `str.format`.
- Первый импорт архива сохраняется с `is_seen=1`. Ошибка отправки оставляет
  раздачу непросмотренной. Дедупликация зависит от источника: AniLiberty обновляет
  раздачу при том же id, поэтому учитывается hash.
- Перед заявлением о готовности пройти путь от пользовательского действия до
  вызова новой функции: в проекте уже оставался покрытый тестами мёртвый код.
- `tests/fixtures/**` хранится без нормализации строк (`.gitattributes`), включая
  windows-1251 HTML. Не перезаписывать такие фикстуры текстовым форматтером.
